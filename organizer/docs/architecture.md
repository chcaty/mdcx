# Architecture decisions and next boundary

## ADR 001: native workbench and small domain core

Avalonia is the desktop shell, C# records/services are the domain core, Microsoft.Data.Sqlite owns the local index, and a Python 3.12+ JSONL child process is the scraper boundary. No React dependency, local HTTP server, listening port, or paid grid control is needed. The optional metadata client uses outbound HTTPS only after explicit source enablement and query initiation. The legacy app remains byte-for-byte unchanged at the base commit. Windows x64 is the first packaged target; development and portable checks also run on Linux. Cross-platform core APIs are retained, while macOS remains unverified.

`Organizer.Core` knows nothing about UI, SQLite, or Python. `Organizer.Infrastructure` owns indexing and subprocess lifetime. `Organizer.Desktop` owns presentation state, explicit review and selection/generation guards. `worker/` owns parsing, validation, source policy, bounded scheduling and replay diagnostics. Protocol schema is versioned; C# tolerates unknown additive fields but rejects incompatible versions, oversized output, invalid candidates and premature process exit.

## ADR 002: source preservation precedes automation

A media asset is a specific video path, not a title/identifier. Versions and possible duplicates remain separate; content equality is not inferred. Scanner IDs hash the full source path; size+mtime fingerprints are change detection, **not content hashes**. Sidecars require unambiguous stem ownership. Unknown names can be manually reviewed. Ambiguous sidecars block planning until future ownership review exists.

Plans are deterministic immutable data. Case-fold/NFC collision checks are conservative across platforms; links/reparse points are skipped/blocked, target ancestors are checked, and path length is constrained conservatively. Metadata cannot inject directories. All plan operations are suggestions only. A rescan can race with filesystem changes: no claim of a locked snapshot is made. A future executor must revalidate and use platform-specific safe handles immediately before each operation.

The scanner currently returns a complete read-only scan result; it is cancellable and the UI list is virtualized, but it is not a streaming million-file index. Next scaling work is bounded scan batches, progress, source-watch reconciliation, cancellation-aware target lookup and measured benchmarks. No throughput claims are made.

## ADR 003: local index ownership

SQLite schema `user_version=1` creates scans, assets, reviews, plans and tasks in one migration transaction. A single asynchronous semaphore serializes connection access; blocking SQLite operations run away from the UI thread. WAL, foreign keys and bounded busy timeout are enabled. Scan refresh is atomic. Incomplete scans never prune missing assets/reviews. Review writes require the fingerprint the user actually inspected and reject a newer indexed fingerprint. A changed fingerprint removes an old review; removed paths cascade review deletion. Repeated plan IDs upsert rather than multiply. Future-schema databases are refused without destructive downgrade.

Manual review is the authority for this slice. Candidate parsing does not directly update an accepted review, file, NFO or image. Stored provenance preserves the basis of acceptance. Before real metadata replacement is added, implement a field diff with `manual/locked > existing verified > new scrape`, explicit replacement policy, raw/original title separate from display/translation, and per-element provenance for lists.

The redesigned workbench stamps a deterministic media-group snapshot over the media and sidecar path/change-fingerprint tuples. This is still size/mtime change detection, not content hashing. Stamped sidecar changes invalidate persisted reviews. First edit withdraws only the exact prior review JSON and matching indexed fingerprint; a delayed editor cannot erase a newer review. Each confirmation has a unique identity, and committed-but-not-yet-applied writes are tracked and withdrawn if selection/cancellation/close supersedes them. Close cleanup is bounded; I/O or cleanup failures remain a limitation, not a crash-recovery guarantee. Legacy unstamped reviews are kept in storage but surfaced for re-review.

Checked batches and focused rows are distinct presentation state. Filtering retains hidden checks; matching is sequential and capped at 50 per batch, without automatic acceptance. The review queue is an explicit checked-row snapshot. Candidate/query changes cancel pending review generations. A naming draft invokes the same pure path planner but is excluded from stored reviewed plans. Session draft/cache preservation requires an unchanged group snapshot.

## ADR 004: worker lifetime and scheduling

Version 1 uses newline-delimited JSON on stdin/stdout; stderr is diagnostics only. Each demo-mode .NET match uses an isolated child process, drains both output streams concurrently, bounds event size/count/candidates, enforces a deadline, ignores stale request IDs, and terminates the running worker tree on cancellation or completion with bounded pipe teardown. This is process separation, not a security sandbox: an arbitrary replacement worker can access the user account, and orphan descendants after a parent has already exited are not guaranteed to be killed. The shipped fixture worker spawns no children. This deliberately avoids long-lived cross-request contamination in the first slice. The worker itself supports bounded concurrent requests, duplicate-ID rejection, terminal-state discipline and a cancellation command, and supports the configured session described below.

Candidate fallback is ordered/lazy; traffic is not blindly fanned out. Provider-internal identity, namespaced catalog identity and display ID are separate typed concepts. xcity detail route IDs identify provider records while hinban supplies an xcity:hinban catalog value; ThePornDB slugs identify provider records only. Equal-looking unqualified strings across those namespaces cannot authorize merging. Historical search/detail route and wrapper contracts are exercised by strict, socket-free request replay; this is not validation of current live sources. The scheduler bounds global/per-host work and retries only transient failures while respecting Retry-After. Source health is diagnostic, not metadata accuracy. Demo mode remains fixture-only. The configured source has a visible explicit save/enable boundary; neither startup nor scanning nor changing settings triggers a query. The actual parser migration and protocol are documented by the worker.

## ADR 005: explicit configured metadata sessions

The source configuration is a credential-free JSON snapshot beside the app-owned index. Missing/invalid settings fail closed to demo mode; optional proxy configuration must omit usernames/passwords. Saving a real source switches the client but does not start a process or query. The first explicit match starts one persistent worker for that configuration. Up to eight admitted requests are serialized, preserving per-host rate/cooldown state across files. A session has a bounded 8192-request lifetime and never restarts silently after a fault or budget exhaustion. Re-saving settings creates a replacement; UI messages explain this recovery.

Admission is tracked before work begins. Cancellation waits for a bounded worker acknowledgment before reuse; failed acknowledgment stops the session. Both pipes drain independently with size/event/candidate budgets. Configured terminal frames must agree with observed candidate/error counts. Startup, cancellation, process kill, callbacks and disposal avoid nested client/session locks; shutdown awaits tracked work within bounded teardown. Settings changes invalidate in-flight UI generations. This is still process ownership, not an OS sandbox.

The standalone JavBus subset accepts only reviewed catalog routes on one fixed HTTPS origin. Page-extracted identity must match the query; request values never fill missing response identity. Current fields are identifier/title/optional year plus provenance, with human review mandatory. HTTPX is pinned, TLS verification is required, ambient proxy/auth/cookies and redirects are disabled, and streaming/time/rate/retry limits are enforced. The package includes hash-locked HTTP dependencies and an isolated Python search path. Current verification is neutral injected HTTP only; source availability, terms/access requirements and current live-page structure remain unverified.

## ADR 006: portable data ownership

The default Windows distribution is a ZIP containing the self-contained app and its private Python worker. A strict `portable.json` marker selects fixed `data/` storage beside the executable. The archive never ships that directory. A manifest-identified portable build with a missing marker fails closed rather than loading an unrelated installed-app index or source configuration. Normal portable startup verifies its data location and presents a readable error when unwritable; it never silently falls back to LocalAppData.

Upgrades replace program files while retaining the user's `data/` directory. The application does not automatically migrate, remove or merge data from an earlier installer. Developer/headless and native acceptance diagnostics retain explicit temporary-path isolation. No registry entry, Start-menu shortcut, automatic updater or user-device installation is required for portable use.

## Future execution journal (design only, not enabled)

1. Persist immutable reviewed plan, source identity/fingerprint, target nonexistence, per-item desired operation and user approval boundary. Never treat an old preview as execution permission.
2. Acquire an application execution lease; resolve source/target to safe platform handles; reject links/reparse surprises, case/Unicode conflicts, stale bytes and cross-device ambiguity.
3. Write a durable `prepared` journal entry before any filesystem mutation. For cross-volume copies, write a temporary file in the target directory, verify size/content hash and flush before atomic no-overwrite publish. Source deletion needs a separate committed step, never inferred from successful copy.
4. Mark each operation `published`, then `committed`; preserve enough data for idempotent crash recovery. Sidecars are separate journalled items in the same group. Interrupted groups remain visible rather than silently declaring success.
5. Undo verifies the current target still matches the journalled identity and original path remains free. It must never overwrite newly created data. Explain non-reversible outcomes and ask at the proper permission boundary.

Before enabling execution: platform integration tests for no-overwrite semantics, hardlinks/reparse points, crash injection at every journal transition, disk-full/permission errors, cross-volume moves, interruption/restart, rollback races, and independent safety review. None of this design is represented as implemented today.

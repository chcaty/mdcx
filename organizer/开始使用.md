## 运行

安装 .NET SDK 10 和 Python 3.12 或更新版本。在本目录执行：

```sh
dotnet restore MediaOrganizer.sln --locked-mode
dotnet run --project src/Organizer.Desktop
```

Windows 默认寻找 `python`，Linux/macOS 默认寻找 `python3`；可用 `-- --python /路径/python` 指定。旧 MDCx 的 Python 3.13.4 环境需求与这个独立样例 worker 是两回事。

建议先用 `python3 scripts/create_demo.py` 生成临时样例文件夹，再在工作台选择输出的 source 路径。样例是不可播放的占位文件，没有真实媒体。识别 DEMO-001 后可以查看候选、人工确认、查看视频与字幕的目标路径。

## 这轮刮削优化落在哪里

- 详情编号不符时拒绝，不能靠“页面请求成功”当作匹配正确
- 来源按优先级惰性回退；站内 ID、带命名空间的番号与展示编号分开，不能把 ThePornDB 的 slug 当作 xcity 番号补字段
- 不用空值/低优先级冲突值覆盖好字段；保留字段来源、原值、转换与审核原因
- 标题歧义保留多个候选，界面展示证据类别并要求人工确认
- 有界全局/站点并发，短暂错误重试，遵守 Retry-After，支持取消和来源健康诊断
- 参考 Javinizer-Go、JavSP、tinyMediaManager 的字段来源、编号核验与补缺思路，独立实现并使用虚构回放夹具验证

目前只有 xcity 搜索/详情 HTML 与 theporndb_movies 搜索列表/详情 JSON 的窄字段契约，使用手工编写的结构参考夹具和严格请求回放；没有采集真实响应，没有连接实时站点，未迁完 38 个来源。没有用样例成功率代替真实刮削准确率。

## 安全和完成边界

所有整理动作目前都只生成预览。没有移动、改名、覆盖、删除或 NFO 写入入口。重复版本、路径冲突、符号链接、字幕歧义、扫描后的文件变化会阻止错误计划。人工审核与任务记录保存在应用自己的 SQLite 索引。

离线契约修正后，在 Linux 完成：32 项核心/进程检查、24 项界面流程检查、138 个 Python 测试；完整 Release 编译零警告零错误。截图来自此前真实 Avalonia 渲染，本次未改界面，视觉改版另行评审。Windows/macOS 真机与系统文件选择器尚未验收。运行时平台、来源权限与真实刮削样本确认后，再做联网适配和可恢复执行。当前版本不是可替换日用旧程序的完整发行版。
